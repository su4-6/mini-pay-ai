# MiniPay Spring AI 学习与改造地图

> 这是原 30 天 MiniPay 主线的增量轨道，不替代 Java、RocketMQ、Docker、Kubernetes、可观测性或 CI 学习。所有“当前已有”必须能在源码或测试中找到证据；所有“待改造”只能写为规划，不能写入简历的已完成能力。

## 当前已确认的能力与边界

| 能力 | 源码证据 | 当前可以怎样讲 | 不能夸大的地方 |
|---|---|---|---|
| Spring AI 模型接入 | 根 `pom.xml` 的 Spring AI 1.1.8 BOM；`agent-service` 的 OpenAI starter | 通过 OpenAI-compatible `ChatClient` 接入模型 | 不等于生产级多模型高可用 |
| 模型调用保护 | `SpringAiModelGateway`：超时、32 路 `Semaphore`、模型忙/失败转换 | 普通流式回答和记忆候选提取受实例内并发保护 | 未完成转账分类尚未复用同一许可保护，列为 AI-001 |
| SSE 流式输出 | `AgentRunSseController`、`AgentRunProcessor` | Run 事件可流式推送，支持 `Last-Event-ID` 续接 | SSE 断线不等于业务 Run 自动取消 |
| Agent Run 准入 | `AgentRunApplicationService`、`agent_user_run_gate` | 通过数据库锁、幂等键与状态机控制同用户/会话 Run | 不把它说成分布式任务平台 |
| 敏感输入保护 | `SensitiveInputSanitizer` 及测试 | 密码、验证码、完整 Token、私钥会拒绝；完整手机号会脱敏 | 仍需持续新增回归样本 |
| 工具调用边界 | `AgentToolRegistry`、`AgentBusinessOrchestrator` | 模型只能经白名单工具/API 调权威服务；写操作需要授权/确认 | 模型不能直连业务数据库、不能直接改余额 |
| 记忆上下文 | `MemoryContextService` 与记忆确认流程 | 当前是用户确认后的显式记忆上下文 | 无向量库、Embedding、Retriever 证据，不能称 RAG |

## 学习与表达红线

- AI 只可调用白名单工具/API；不得直接读写 Payment、Wallet、Commerce、Identity 的数据库。
- 不把密码、支付密码、验证码、完整 Token、私钥、完整手机号放进模型提示词、日志、指标或长期记忆。
- 资金动作仍由 Payment/Wallet 等权威服务、授权令牌和确认流程决定；模型只做受控建议或编排入口。
- 计划、设计、待测试内容不能写成“已上线”或“性能提升”。
- 每次改造均遵循“先测试，再最小实现，再运行受影响模块测试”。
