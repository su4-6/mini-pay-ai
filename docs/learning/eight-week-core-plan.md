## 目标与边界

- 目标：以每周 12--16 小时完成 Day 4--30 的后端校招核心主线，形成可验证的源码、实验和口述证据。
- 目标岗位：Java 后端校招；Kubernetes 和 CI/CD 学到可交付、可排障、可解释边界的程度，不按平台运维岗位深挖。
- 当前起点：Day 4 已于 2026-09-05 完成；下一单元是 Day 5 的 JVM、GC、类加载与 OOM。
- K8s 预习：`deploy/k8s-learning/` 是预习材料，不构成 Day 22 的完成证据；正式 Day 22 前须确认其分支归属和运行记录。
- 保持架构约束：Kubernetes 只承载无状态业务服务；MySQL、Redis、RocketMQ、Seata 继续由 Compose 承载。不引入 Nacos、Gateway，不跨服务读写数据。

## 每个学习单元的完成门槛

每个 Day 必须同时满足以下条件才可标记完成：

1. 读懂一条真实 MiniPay 源码链路；一次最多追踪三个核心入口。
2. 完成一个最小实验、定向测试或可复现的运行观察，并记录实际结果。
3. 完成当天 3--10 道口述题；答不清的题写入错题或补课台账并安排复习日。
4. 记录一条项目边界或故障判断，明确“该机制解决什么、不解决什么”。

没有运行/测试证据或口述未通过时，保留在当前单元继续；不得以提前学习后续主题替代未完成项。提升项允许只做一次示例和用途说明，后续深度项写入 Day31--37 或更后的清单，不阻塞核心主线。

## Kubernetes 学习闭环（Day 22--24）

### 必会

- Pod、Deployment、ReplicaSet、Service 的分工；能用 `kubectl get`、`describe`、`logs`、`exec` 检查问题。
- ConfigMap、Secret、readiness/liveness probe、CPU/内存 requests 和 limits；能解释未就绪、重启和资源受限的现象。
- Ingress、Kubernetes Service 服务发现、滚动更新和回滚。
- 为一个无状态服务走通：镜像 → Deployment → ConfigMap/Secret → Probe → Service → Ingress → 更新 → 回滚 → 日志定位。

### 提升与暂缓

- 提升：完成一次 Helm、HPA、Namespace 或 NetworkPolicy 示例，并说明其解决的问题。
- 暂缓：etcd、CNI、Operator、集群高可用、生产 GitOps、复杂 StatefulSet 运维。它们不作为本轮后端校招验收内容。
